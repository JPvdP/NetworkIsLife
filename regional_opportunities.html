Identifying Class Connections and Regional Opportunities

Author

Published

Invalid Date

1 Goal

We have 40 classes, 10 regions, and 500 players. Each player can belong to up to 3 classes.
We want to:

  1. Find which pairs of classes frequently co-occur across the whole dataset (a class co-occurrence network).
  2. For each region, identify opportunities: class pairs that are common (or meaningful) globally but underused or missing locally.

This document lays out a concept-to-implementation plan you can translate into code.

2 1) Data structure

  • Players table: 1 row per player with their region.
  • Membership table: 1 row per (player, class) pair.
    • Deduplicate within a player (a class appears at most once per player).
    • Each player has 1–3 rows here.

3 2) Global class–connection network

We’re interested in unordered pairs of classes that co-occur within the same player.

  1. For each player with \((k)\) classes (max 3), list all \((\binom{k}{2})\) unordered pairs.
  2. Tally across all players to get counts \((C_{ij})\) for each pair \(((i,j))\).
  3. Also compute single-class counts \((f_i\)) = # players with class \((i)\). Let \((N)\) = # players.

Common association metrics for each pair:

  • Support: \((\text{supp}_{ij} = C_{ij}/N)\)
  • Jaccard: \((\text{Jac}_{ij} = \dfrac{C_{ij}}{f_i + f_j - C_{ij}})\)
  • Confidence (directional):
    \((\text{conf}(i\rightarrow j) = C_{ij}/f_i,\quad \text{conf}(j\rightarrow i) = C_{ij}/f_j)\)
  • Lift: \((\text{lift}_{ij} = \dfrac{C_{ij}/N}{(f_i/N)(f_j/N)})\)
  • PMI: \((\text{PMI}_{ij} = \log \dfrac{C_{ij}\cdot N}{f_i f_j})\)

Pick one or two as the global strength (e.g., Lift + Support).
This yields a network: nodes = classes; edges weighted by strength.

Tip: With 40 classes, there are (=780) pairs—easy to compute. Use small Laplace smoothing if needed to avoid division by zero.

4 3) Regional versions

For each region \((r)\):

  • \((N_r)\): # players in region \((r)\)
  • \((f_{i,r})\): # players in region \((r)\) with class \((i)\)
  • \((O_{ij,r})\): observed pair count in region \((r)\)

Optionally compute regional Support/Jaccard/Lift the same way, restricted to players in \((r)\).

5 4) Defining “opportunities”

We want pairs that are meaningful globally but underused locally versus an expected baseline. Three complementary baselines:

5.1 A. Global benchmark rate

  • Global co-occurrence rate: \((p_{ij}^{(global)} = C_{ij}/N)\)
  • Expected in region: \((E^{(A)}_{ij,r} = N_r \cdot p_{ij}^{(global)})\)
  • Opportunity score A: \((\max\{0, E^{(A)}_{ij,r} - O_{ij,r}\} \times \text{strength}^{(global)}_{ij})\)

Pros: Simple; measures “catch-up to global pattern.”
Cons: Ignores local availability of \((i)\) and \((j)\).

5.2 B. Local independence baseline

  • Local class rates: \((p_{i,r} = f_{i,r}/N_r,\quad p_{j,r} = f_{j,r}/N_r)\)
  • Expected if independent locally: \((E^{(B)}_{ij,r} = N_r \cdot p_{i,r} \cdot p_{j,r})\)
  • Opportunity score B: \((\max\{0, E^{(B)}_{ij,r} - O_{ij,r}\})\) (optionally weight by global strength)

Pros: Accounts for local supply of both classes.
Cons: Assumes independence.

5.3 C. Degree-preserving permutation (statistically rigorous)

Within each region \((r)\), build a null by randomizing while preserving:

  • each player’s number of classes (1–3),
  • each class’ regional frequency (f_{i,r}).

For each shuffle, recompute pair counts (O^{(s)}{ij,r}). This yields a null distribution with mean ({ij,r}) and sd (_{ij,r}). Compute a z-score or p-value for depletion:

[ z_{ij,r} = z_{ij,r} . ]

Opportunity rule: low observed, high expected under null, and significant depletion (FDR-corrected p-value small). Weight by global strength to favor system-wide important pairs.

6 5) Ranking opportunities per region

For each region (r), build a table:

  • Pair ((i,j))
  • Global strength (e.g., Lift, Support)
  • (O_{ij,r}) (observed)
  • Expected (E_{ij,r}) (choose A, B, and/or null mean (_{ij,r}))
  • Gap (={0, E_{ij,r} - O_{ij,r}})
  • (If using C) p-value and FDR q-value

A simple composite:

[ {ij,r} = (^{(global)}{ij}) (_{ij,r}) { } ]

Sort descending; report the top (K) per region.

7 6) Visualizations

  • Global network: nodes = classes; edge width = Support, edge color = Lift (or PMI).
  • Regional opportunity heatmap: rows = regions, cols = top pairs; values = Gap or OppScore.
  • Per-region bar chart: top 10 opportunity pairs with Gap labels.

8 7) Extensions & notes

  • Triples: because players can hold 3 classes, you can mine 3-item sets (triads) via Apriori/FP-growth; start with pairs for clarity.
  • Multiple testing: if using permutation p-values, control FDR (Benjamini–Hochberg).
  • Sparsity: consider modest smoothing for Lift/PMI.
  • Data hygiene: ensure per-player class memberships are unique (no duplicates within a player).

9 8) Minimal implementation sketch (pseudo-code)

This is intentionally high-level; translate to R/Python as you prefer.

  1. Explode memberships to pairs per player
    For each player: form all unordered class pairs; deduplicate pairs per player.

  2. Global tallies

    • Count (C_{ij}) for each pair; count (f_i) for each class; compute (N).
    • Derive Support/Lift/Jaccard/PMI.

  3. Regional tallies

    • For each region (r): compute (N_r), (f_{i,r}), (O_{ij,r}).
    • Compute expectations (E^{(A)}{ij,r}) and/or (E^{(B)}{ij,r}).
    • (Optional) Run degree-preserving permutations to get ({ij,r}, {ij,r}), and p-values.

  4. Scores & ranking

    • Compute Gap and OppScore per pair-region.
    • Sort and output top opportunities per region.
